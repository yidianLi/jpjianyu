移动APP ↔ 后端 API契约 APP独立开发 · 与PC解耦 · 共用业务库

BaseUrl: http://10.8.0.12:8080/api/v1 · 认证 Authorization: Bearer <token> + X-Device-Id · 全部数量必带 qty+unit · 错误码：SIGN_REQUIRED / DUP_SCAN / OVER_ISSUE / SCOPE_DENIED

1. POST /auth/app-login
req: {username, password, deviceId}
res: {token, expiresIn:28800, user:{name,role,scope}}

车间账号登录后 scope 仅本车间，服务端按 user_data_scope 过滤。

2. GET /app/todos?mine=1
res: [{id,type,title,desc,deadline}]
TL退料 / ZS直送 / DB调拨 / LY领料
3. POST /app/scan（SB必扫/箱唛可选）
req: {code, orderId}
res: {result:OK|DUPLICATE|INVALID|MISMATCH,
 material, qty, unit}

重复/超领/非本单/客户不一致由服务端拦截，对应 scan_record。

4. POST /app/ocr（拍照→候选值）
req: {images:[base64…]} // APP端压缩
res: {candidates:{customer,qty_ocr,conf},
 ocrId:OCR2026091201}

只返回候选，人工值覆盖，对应 ocr_document + ocr_field_result。

5. GET /app/checklists + POST /app/checklists/confirm（清单验收）
GET  req: ?orderId=SL2026091209
res: {orderId, status, items:[{code,batch,unit,deliveryQty,receivedQty,checked}]}
POST req: {orderId, items[], operator, deviceId}
res: {status:ACCEPTED|PENDING_SYNC}

逐项核对编码/批次/单位/数量；数量有差异必须带 reason，移动端与PC验收写同一业务单据。

6. POST /app/submit（签名必填）
req: {orderId, codes[], qty, unit, sign}
res: {orderId} / {code:SIGN_REQUIRED}
离线: 写 mobile_sync_queue, 联网补传
7. GET /app/orders?mine=1 · 数据查看
服务端按仓库/客户/监区楼层车间过滤
PC报表/审计读同一张表：material_transaction, audit_log

APP永不调 /web/*，PC永不调 /app/*，联调以单号为准。
