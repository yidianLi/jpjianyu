# 技术决策的处理方式 V1.0

> 版本：V1.0 / 2026-09-20 / 状态：冻结，长期引用
> 适用：本项目一切技术决策、发 Cursorcore 清单、核查分级、阶段验收。
> 语言：中文为主；代码注释、字段名、技术词汇用英文。不堆表情，不情绪化结尾。

## 一、永久性约束要警惕 [PERMANENT]

一旦定型长期不能改（数据库字段类型、维度、命名空间、对外契约）：

- 显式标注 `[PERMANENT]`，多方案对比，不轻易拍板。
- 文档留“为什么这么定”，后人可回顾动机。
- 本项目永久约束：
  - P1 单据前缀 `DJ/RK/LY/TL/PD` + `idem_key=doc_no:line_no:biz` 唯一。备选 UUID/雪花 ID 弃用：前缀人可读、PDA 可扫可念，改了历史单全断。动机：幂等+溯源同键。
  - P2 `stock_ledger` 只增不改，`PD` 不动账。备选直接改现存弃用：无审计不可溯。动机：`Σledger=on_hand` 可仲裁。
  - P3 命名空间 `/api/v1/web|app|ai` 三分。备选合一弃用：AI 只读与过账混权。动机：禁过账可强制。
  - P4 溯源到 `BT` 批级，数量必带 `qty+unit`。备选 SB 单件到底弃用：写入成本翻倍，MVP 不需要。动机：够用+便宜。
  - P5 错误码 `DUP_SCAN/OVER_ISSUE/SCOPE_DENIED`。改了 PDA/PC 双端重写。

## 二、可逆性决策快速决定 [REVERSIBLE]

定错可改（代码实现方式、模型选型）：给推荐+理由，用户说“按推荐来”直接做，不反复纠结。

- R1 模型百炼现阶段→内网 vLLM。推荐按此来：`adapters/qwen.py` 已隔离，改配置不改代码。
- R2 OCR 线上兼容→本地 Paddle。推荐按此来：`adapters/paddle.py` 同理。
- R3 PDA 先键盘楔。推荐按此来：`pda-scan.js` 单点可换广播。
- R4 问答默认快照、仲裁流水。推荐按此来：快+准兼得。

## 三、风险点显式管理 [RISK]

- 待验证事项进清单，不漏。当前：
  - RISK1 百炼 `qwen2.5-7b-fp8` 兼容接口路径/计费：知识截止后事实，需搜索验证或标需用户确认，P6 验收。
  - RISK2 vLLM FP8 显存/镜像版本：P7 前验证。
  - RISK3 PDA 广播 Intent 名：等厂家文档，需用户确认，现冻结键盘楔。
  - RISK4 线上 OCR endpoint：需用户确认，先 Mock。
- 第三方 API/爬虫/价格/政策：主动搜索验证，验不到标“待用户确认”，不凭印象给方案。

## 四、模型/工具选型的灵活性

- 对话模型、embedding、第三方 API 优先接口规范化：业务不直绑服务，经配置/适配器隔离。
- 落点：`adapters/qwen.py + adapters/paddle.py + config/ai-gateway.yaml`，后期改配置不改代码。

## 五、代码约束

- 单文件不超过 300 行，按阿里巴巴开发规范。
- 超标治理（现状 `material-workbench.html 1310 / app.js 775 / finished.html 612 / ai.html 315`）：
  - 后端 `routers/ai|web|app_`、`core/guards|auth|idem`、`adapters/*` 单文件均 ≤300 行。
  - 前端超标页按视图/组件/桥拆，不新增业务页。`screens/*.html` 单行压缩行数失真，按逻辑拆。
  - P1 起执行。

## 六、配合 Cursorcore 的要点

1. 发 Cursorcore 的清单格式：一份 Markdown，可整段复制粘贴；含关键代码骨架、字段名、错误处理要求，减少自由发挥；末尾标出期望改完发回检查的文件清单。
2. 不让 Cursorcore 做关键决策：字段命名、状态机、模块边界必须在清单里给定；Cursorcore 只按指令实现，不决定设计。
3. 核查分级：Cursorcore 产出按 🔴/🟡/🟢 分级修正。🔴 阻断（运行会爆、设计硬伤）必须改；🟡 稳健性问题，改了更好；🟢 优化建议，记下以后做。不全标 🔴。
4. 阶段验收走端到端：不只看代码是否按清单写，跑一遍端到端看产出；验收点可量化可观测：具体 SQL、文件是否出现、日志关键字、DB 状态变化。

## 七、特殊情境处理

- 信息过期/不确定：第三方 API、爬虫、价格、政策主动搜索验证；验不到标待用户确认，不猜。
- 排查问题：先列最可能原因+验证步骤，用户跑完定位再给针对性方案；一次给多个可并行方向。
- 沟通失误/返工：不道歉，直接说“我之前没考虑到 X，改正方案是 Y”。
- 用户挑战观点：认真考虑，不立刻让步；对则认错修正，错则指出误解点，不模棱两可。
- 长对话管理：阶段验收节点主动建议起新对话+给继承核心信息总结，不等卡死。
