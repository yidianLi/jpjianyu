# 代码审查标准（WMS 项目 · V1.0）

> 适用范围：监狱公司物料管理系统（后端 FastAPI / Node.js AI 网关 / 前端静态原型）。
> 维护人：研发团队 · 审查专家「火眼眼」
> 配套文档：《代码审查流程.md》

本标准的目的是把"代码质量参差不齐"从**靠个人自觉**变成**靠规则与门禁**。所有合并到 `main` 的代码都必须先过本标准。

---

## 一、严重级别定义

每条审查意见必须带一个级别标记，禁止只写"这里不太好"。

| 级别 | 含义 | 合并门槛 |
|------|------|----------|
| 🔴 **阻断（Blocker）** | 安全漏洞、数据损坏/丢失、破坏接口契约、缺少关键错误处理的路径。**不修不准合并。** | 必须清零 |
| 🟡 **建议（Suggestion）** | 输入校验缺失、命名/逻辑混乱、重要行为无测试、性能隐患、应抽取重复代码。**应尽量修，可协商。** | 0 个未处理（或显式记录"已知技术债"） |
| 💭 **吹毛（Nit）** | 风格不一致、微小命名、文档缺口、值得考虑的替代方案。**不阻塞合并。** | 可选 |

**原则**：审查是教学，不是关卡。每条 🔴/🟡 都要写 **为什么（Why）** 和 **建议改法（How）**，不要只说"有安全风险"。

---

## 二、通用审查清单（所有语言）

### 🔴 阻断项
- **密钥与凭证**：任何密码、API Key、token、内网地址**不得写进源码**。必须走环境变量 / `config/.env`（已 gitignore）。
- **注入风险**：SQL 拼接用户输入、命令注入、模板注入、前端 XSS（未转义渲染用户数据）。
- **鉴权缺失**：任何写操作（建单/过账/出入库/改权限）必须有鉴权与权限校验。
- **静默吞错**：`except: pass`、把异常转成"成功"、错误被吞导致下游误判（本项目曾出现"过账 404 误报成功"，见 git 历史 `45364bb`）。
- **破坏接口契约**：改了请求/响应字段或状态码，未同步更新 `docs/api-*.html` 与调用方。

### 🟡 建议项
- 函数/文件超过约定上限（本项目约定**单文件 ≤ 300 行**）应考虑拆分。
- 魔法数字 / 硬编码配置（超时、白名单、设备号）应抽成常量或配置。
- 重复代码（尤其**跨语言重复**的护栏/白名单，见下文第五节）应抽到单一真相源。
- 公共函数缺少类型标注（Python 用 `type hints`，JS 用 JSDoc）。
- 重要分支逻辑无测试。

### 💭 吹毛项
- 注释语言不一致、日志格式不统一、变量名 `a/b/tmp` 之类。

## 三、Python / FastAPI 专项

- **ORM vs 原生 SQL**：优先用 SQLAlchemy 2.0（`select()` / 参数化），禁止 f-string 拼 SQL。
- **依赖注入**：DB session 统一走 `get_db` 依赖，禁止在函数内自己 `create_engine`。
- **Pydantic 校验**：所有入参走 `pydantic` `BaseModel`，不在路由里手写 `request.json()` 后直接信任。
- **异步一致性**：路由与 DB 调用保持 async/await 一致；阻塞 IO 用 `httpx.AsyncClient` 而非同步 `requests`。
- **错误响应**：统一走 `app/core/resp.py` 的响应结构，不要各路由自己 `return {"ok": ...}` 不一致。
- **幂等**：写操作（建单、过账）须有幂等键 / 业务号去重（本项目已有 `idem.py`，审查时确认其被调用）。

## 四、Node.js / AI 网关专项

- **零依赖约束**：`ai-gateway` 当前 `dependencies: {}`，若需加包须评审（保持单文件 ≤ 300 行）。
- **请求体解析**：`bodyOf` 解析失败应返回 400，而非静默 `res({})`（当前实现会吞掉坏请求）。
- **护栏与后端一致**：JS 侧白名单/拒词必须与 Python `guards.py` **同一份数据**（见第五节）。
- **CORS**：网关仅本地 `127.0.0.1` 调用，不要 `Access-Control-Allow-Origin: *`。
- **密钥**：`LLM_API_KEY` 只来自环境变量，绝不下发前端。

## 五、前端静态原型专项

- **无构建步骤**：保持纯静态，不引入打包器；如需变量用 `store.js` 统一管理。
- **XSS**：`innerHTML` 渲染接口数据前必须转义；曾修过 XSS 转义问题（git `45364bb`）。
- **接口约定**：fetch 的 URL / 字段须对齐 `docs/api-*.html`，改后端要同步改原型。
- **误提交垃圾**：原型目录只放可运行资源，**截图 / `.rar` / `prototype.rar` / 解析脚本**等已 gitignore，审查时若发现被提交应拒收。

## 六、安全红线（本项目重点：敏感政企数据）

WMS 涉及监狱物料，数据敏感，**安全级别整体上调一档**：

1. **凭证零落地**：`app/core/db.py:6` 当前把 `mysql+pymysql://wms:wms@10.8.0.10:3306/wms` 写死在源码——🔴 必须改为纯环境变量，源码里只留 `os.getenv("DB_URL")`。
2. **CORS 收紧**：`app/main.py:10-11` `allow_origins=["*"]` 对内部系统过大——🔴 改为明确的前端域名/局域网白名单。
3. **AI 出 SQL 的护栏必须可靠**：当前用正则白名单（`guards.py` + `server.js`）。正则拦 SQL **可被绕过**（如注释、换行、编码混淆）。生产环境 🔴 级要求改用 **SQL AST 解析**（如 `sqlglot`）做结构校验，或只允许预定义查询模板。
4. **跨语言护栏漂移**：`guards.py` 的 `ALLOW` 有 10 张表，`server.js` 的 `ALLOW_TABLES` 只有 6 张（且注释写"三域"实为 6 张）——🔴 不一致意味着同一句话在两端结果不同。**必须抽取为单一配置文件，两端共用。**
5. **Token 存储**：`auth.py` 的 `TOKENS = {}` 是进程内存字典，重启即失效、多 worker 不共享——🟡 原型可接受，但**上线前必须换 Redis / JWT**，并在审查 checklist 标注"已知技术债"。
6. **审计日志**：所有写操作需留痕（谁、什么设备、何时、改了什么），供事后审计。

## 八、审查评语写法规范

统一格式，便于追踪：

```
🔴 安全：数据库凭证硬编码
文件 app/core/db.py:6
Why：源码入库即泄露内网账号密码，任何人 clone 即得控制权。
How：改为 DB_URL = os.getenv("DB_URL")，真实地址仅存于 config/.env（已 gitignore）。
```

- 一句结论 + 文件:行 + Why + How。
- 争议点用提问代替断言："这里用内存字典是刻意为原型简化，还是遗漏了多实例场景？"
- 好的写法要表扬：发现 `guards.py` 用白名单思路拦写操作，方向正确，值得保留并强化。
