## 1. 工作台（4个）：看数 + 入口

- 首页 `home.html`：截图大屏。常用应用10图标=各工单快捷入口；今日待办日历；交接中心4待办（SL送货单/TL退料/PD盘点/CP成品）；业务数据健康卡；库存概览（牛津布6,300米·拉链2,000件）；WH-A/WH-B分仓卡；14天出入库曲线。
- 驾驶舱 `dashboard.html`：三域聚合（待办/库存/差异/周转+产能），无设备、无人均、无当班人数。异常卡直达 `docs.html?code=` 与 `stocktake.html?pd=`，手动/按班刷新，不做秒推。
- 现场作业APP `mobile-app/index.html`：PDA端扫码直达，不做AI问答、不做OCR识别。
- AI问数 `ai.html`：二期，顶部入口。只读，只给数和单号+公式。
- 结论：工作台不建表，数据全从 `stock_onhand / stock_ledger / doc_main` 聚合。

## 2. 仓储作业（5个）：只管进出地点，不管配方不管价

- 仓库库存→ `GET /api/v1/web/stock/onhand` → `stock_onhand` 快照。按 `wh/loc/material/product` 查；物料行 `product_code=''`，成品行 `material_code=''`。只读。
- 库存记录→ `GET /api/v1/web/stock/ledger` → `stock_ledger` 只增不改。差异仲裁以此为准，只报警不锁。
- 库区管理→ `masters/warehouses + locations` → `warehouse + location`。`WH-A外仓/WH-B内仓1/WH-C内仓2`；`wh_type` 原料仓/成品仓/待检区/隔离区；`stock_kind` MAT/FIN/ALL 决定能不能放；`loc_code` 结构化主键+中文显示名+`qr_code`。有库存只能停用不能删。
- 库存调仓→ `transfer_ships` → `transfer_ship`，DB单（sid=19000）。两段：在途申请 `o_qty` /已发/实收 `n_qty` + `carrier/plate/eta` + `diff_status`。
- 库存盘点→ `pd_tasks` → `pd_task + pd_line`，PD单（sid=13100）。`o_qty账面/n_qty实盘/diff=N-O`。本身不动账，复核后另生 TK/RK 调账。人工临时 + 02:30自动，范围冻结。
- 思考：5个里3只读、2工单。`wh/loc` 只做存在性 + `stock_kind` 校验。

## 3. 物料管理（8个）：消耗侧主线，逻辑最重

- 物料明细→ `masters/materials + mat_categories + stock/batches + items` → `mat_master + mat_category + batch + material_item`。`base/pack/sub` 三计量；`manage_mode` QTY按米 / CODE一物一码；`unit` 必须等于 `base_unit`；`max/min` 写预警。
- 申请领料SQ→ `POST /docs {type:SQ, sid:11600}` → `doc_main/doc_line`。只登记需求，不动 `onhand/avail`，不写 `ledger`。01车间申请/02计划申请。审批后转 LY。
- 物料登记DJ→ `POST /docs {type:DJ, sid:10000}`。建码，初始库存必须0，期初走 RK 单。CODE生成N条码，QTY生成批次。
- 来料拒收JS→ `POST /docs {type:JS, sid:10200}`。凭证不动账。01整批/02部分/99其他。只回写来源单 `qty_reject`。
- 物料入库RK→ `POST /docs {type:RK, sid:10100}` + `post` 过账。`lines` 填 `material_code+qty+unit+loc`，单号 `RK[SERIAL:6]`。过账改 `onhand/avail` + 写 `ledger`。
- 物料领用LY→ `POST /docs {type:LY, sid:10400}`。记领用人/车间/班组/工位，双签。实发≤可用，否则 `OVER_ISSUE`。可按 `bom_version` 自动展开（`wo_tasks/{wo_no}/issue`）。
- 车间退料TL→ `POST /docs {type:TK, sid:15000, bmid:01余料回仓}`。须关联原 LY 单。`avail` 回增，条码回在库。
- 物料退库TK→ `POST /docs {type:TK, sid:15000, bmid:02/03}`。入库冲红生成反向流水，原单转 `REVERSED` 历史不改；损坏退还可关联 JS 单。
- 思考：8个里 SQ/JS 不动账，DJ 建档，RK/LY/TK 动账。TL 与 TK 同表（`sid=15000`）靠 `bmid` 区分（01=车间退料回增，02=冲红，03=退供），前端分两页展示是对的。

## 4. 成品管理（5个）：产出侧主线，与物料平级

- 成品明细→ `masters/products + prod_categories + stock/onhand?product_code=` → `product_master + prod_category`。`CP-` 独立编码，不先建物料码。`style` 款号 / `customer` 归属客户。
- 成品登记CP→ `POST /docs {type:CP, sid:11200}` + `POST /masters/products + /boms`。01成品建档，同时建 BOM 版本。
- 成品入库→ `POST /docs {type:RK, sid:11300}`。`RK` 前缀复用，`sid` 区分物料/成品。`lines` 填 `product_code+bom_version+qty`。01完工入库/02委托回厂。`wo_tasks/{wo_no}/finish` 触发草稿。
- 成品退仓TC→ `POST /docs {type:TC, sid:15050}`。成品反向，关联原 RK/JJ 单。
- 成品交付JJ→ `POST /docs {type:JJ, sid:11400}` + `POST /deliver_signs`。01客户交付/02暂存转出。`deliver_sign` PK即FK=`doc_no`，`receiver+sign_time+proof_ref` 必填。只记数量去向。
- 引擎：`wo_task（product_code+bom_version+qty_plan/qty_done）`，`issue` 按BOM展开领料，`finish` 一轮完工汇总。`bom_master（一成品多版本，启用仅一）→ bom_line（成品⇒物料+loss_rate）` 是两条主线的桥。

## 5. 基础资料（8个）：配置层

- BOM管理 `base-bom` → `bom_master/bom_line`。成品⇒物料配方。V4标二期，但成品入库/领料展开依赖它，建议提前。
- 物料档案 `base-material` → `mat_master`。MVP。严禁业务用户录入，只有管理员可写；业务单只能选启用档案；新增初始0。
- 组织架构·车间 `base-org` → `org_node`。监区/楼栋/楼层/车间/班组/工位，`autocode` 定长3位/级。MVP。
- 仓库档案 `base-warehouse` → `warehouse`。MVP。编码/类型/负责人/启用。
- 库区档案 `base-location` → `location`。MVP。仓库-库区-货架-栏-格，`loc_code` 主键 + 中文显示名。
- 客户档案 `base-customer` → `customer`。MVP。一表两类型（供货单位/委托加工客户），如 KH001 恒达服饰。
- 成品档案 `base-product` → `product_master`。V4标二期，但成品登记要建档，建议跟成品走。
- 单据模板 `base-template` → `doc_template`。二期。`tpl_code` 如 MB-SHD，TEXT存JSON。
- 编码口径：`material_code` 允许 `HD-` 与 `10A-` 双轨并存，新码走 `M+日期+流水`，不强制切换。

## 6. 单据中心（6个）：查 + 工具，不记账

- 业务记录查询 `docs.html` → `GET /docs + /docs/{doc_no} + trace`。全类型15前缀统一检索，`SB/BT/单号` 同一框，全链路追溯。MVP。
- OCR工作台 `ocr.html` → `ocr_document + ocr_field_result`。二期。原图/识别值/人工值/置信度/修改人，只回填候选。
- OCR扫描结果 `ocr-result.html` → 同上。二期。人工确认后入库单才生效。
- 二维码中心 `qrcode.html` → `label_print`。二期。条码/名称/单价/规格/批次，打印即记，支持补打留痕。
- 设备扫码记录 `scanlog.html` → `scan_log`。二期。`HIT/DUP_SCAN/OVER_ISSUE/SCOPE_DENIED`，只增不改。
- 加工费对账 `processing-fee.html` → `fee_settle + fee_settle_line`。二期。一期只出数量，不出金额/发票。
- 思考：单据中心是三线（仓储/物料/成品）的影子，全只读，不开写口。

## 7. 异常与审计（1个）

- 操作审计 `audit.html` → `audit_log（o_val/n_val+device+detail）` + `flow_instance`。字段级前后值。MVP。只读。
- 驾驶舱异常卡汇总待补数直达处理也在此闭环。

## 8. 报表中心（2个）

- 报表中心 `report.html` → `rpt_instance`。12类：收发存/余额/领退/调仓/退料/成品/差异/库龄/损耗/对账/日报/完工。生成草稿只读不改账，发布才可见。二期。
- 报表配置 `report-config.html` → `rpt_config`。列、口径、定时（日报06:00/周报周一/月报次月1日）。二期。

## 9. 系统管理（3个）

- 用户管理 `users.html` → `sys_user（username自然键+data_scope）+ sys_role + sys_perm行式矩阵 + sys_user_role`。MVP。录入≠审批，冲红默认高一档。
- 设备管理 `equipment.html` → `equipment`。PDA/打印机/扫描仪登记。不进驾驶舱。二期。
- 审批流配置 `approve-flow.html` → `flow_def（steps_cfg S1..S6）+ flow_instance`。按 `doc_type` 配级数，是否需民警签名。LY需领用人+发料人双签。MVP最小可用。

## 10. 闭环一句话

`基础资料备料 → 物料8步消耗 → BOM桥 → 成品5步产出 → 仓储5处落点 → 单据6处留痕 → 审计1处查错 → 报表2处汇总 → 系统3处管人 → 工作台4处看数`。

## 11. 数据不乱的4条底线

1. SQ（申请）与 JS（拒收）不动账，PD（盘点）不动账。
2. TK/TC 反向不改历史（反向流水 + 原单转态）。
3. `unit` 必须等于档案 `base_unit`，合计按单位分组，绝不混加。
4. 唯一写入路径：审批过账 → `stock_ledger + stock_onhand`；`idem_key=doc_no:line_no:biz` 唯一；`Σledger = onhand` 不平只报警不锁。
