## 一、正式上线（生产）部署必做清单

按顺序执行，任何一项缺失都可能引发事故。

### 1. 环境变量（三件套务必配齐）
在 `backend/config/.env` 中配置（该文件已 gitignore，不进仓库）：

| 变量 | 必填 | 说明 |
|---|---|---|
| `WMS_ENV` | 生产必填 | 设为 `prod`。未配置=开发模式（带内置弱密钥，禁止上生产） |
| `WMS_JWT_SECRET` | 生产必填 | 64 位随机串；**生产未配置或 <32 位，服务直接拒绝启动**。更换后所有已发 token 失效 |
| `MYSQL_ROOT_PASSWORD` | 生产必填 | 数据库 root 强口令（compose 读取，覆盖默认 `root`） |
| `MYSQL_USER` / `MYSQL_PASSWORD` | 生产必填 | 业务库账号强口令（覆盖默认 `wms/wms`） |
| `WMS_CORS_ORIGINS` | 视情况 | 前端与后端不同源时填前端来源，逗号分隔；同源部署可留空 |
| `WMS_COOKIE_SECURE` | 视情况 | 走 HTTPS 时设 `1`（`WMS_ENV=prod` 已默认开启 Secure） |
| `SEED_DEMO` | 生产设 `0` | `1` 会灌演示账号/主档，生产必须 0 |
| `WMS_BOOTSTRAP_ADMIN` | 生产首次部署设 `1` | 设为 `1` 且库中无任何账号时，按 `WMS_ADMIN_PASSWORD` 自动创建首个管理员（不灌演示数据） |
| `WMS_ADMIN_USER` / `WMS_ADMIN_PASSWORD` | 配合上一项 | 首个管理员账号名（默认 `admin`）与明文密码；创建后请尽快在系统内改密 |

生成强口令示例：`python -c "import secrets;print(secrets.token_hex(32))"`

> **首个管理员怎么来（重要）**：干净库初始化后 `sys_user` 为空，无人可登录。二选一：
> - **生产**：`WMS_BOOTSTRAP_ADMIN=1 WMS_ADMIN_PASSWORD=<强口令> docker compose up -d`，自动建唯一管理员，无演示数据。
> - **演示/试用**：`SEED_DEMO=1 docker compose up -d`，灌入 admin/demo 等演示账号与主档。
> 两者都只在"数据卷为空的首启"时生效；库已初始化则跳过（不会覆盖既有账号）。

### 2. 数据库持久化与自愈（已在 compose 内置，确认生效即可）
- `docker-compose.yml` 已为 mysql 挂命名卷 `mysql_data:/var/lib/mysql` —— **数据落到卷，不再随容器删除丢失**。
- 两服务均已 `restart: always` —— 崩溃/重启自动拉起。
- mysql 有 `mysqladmin ping` 健康检查，api 有 `/health` 探活，api `depends_on: service_healthy` 等库就绪才启动。

> ⚠️ 首次用新 compose `up` 时，若 `mysql_data` 卷为空会按 `sql/wms.sql` 初始化。
> 若要从旧的"无卷"容器**保留现有数据**：先 `mysqldump` 导出 → 全新 `up` 初始化空库 → 导入数据；
> 全新部署（推荐）则直接 `up` 即可，无需迁移。

### 3. 启动与自检
```bash
cd backend
docker-compose up -d --build
python selfcheck.py --base http://<host>:8080/api/v1 --user admin --pass <管理员密码>
# 输出"✓ 演示就绪: N 项通过"即可对外；有 FAIL 项按提示处理
```
- 自检分 5 层：服务健康 / 登录鉴权 / 主数据 / 演示链路（建单→审批→过账→库存→追溯→报表）/ 演示数据。
- 自检会自建自清测试单；如中断残留，跑 `sql/cleanup_selfcheck.sql` 清理。

### 4. 上线后立刻做
- 修改默认管理员口令（`admin/ok` 仅为演示）。
- 确认外网不可达时的 AI 问数降级：网关失败会走"关键词规则"查真数（返回 `mode=rule`），不影响核心业务。

## 三、已知未做项（不影响上线，但长期运营建议排期）

| 项 | 说明 | 建议 |
|---|---|---|
| **数据权限 `data_scope`** | 字段存了但查询未按仓库/客户过滤 | **单单位单点可不上**；将来多单位/多监区前必须先做 |
| 密码哈希无盐 | 现行 `SHA256("wms:"+密码)`，可被彩虹表 | 建议改 PBKDF2/bcrypt，需存量账号兼容迁移 |
| `/health` 不探 DB | 静态返回 ok，DB 挂了仍显示健康 | 建议加 `SELECT 1` 探活 |
| 金额/数量用 float | 长周期累计精度漂移风险 | 建议核心金额列改 DECIMAL/整数分 |
| 前端 innerHTML 转义覆盖不全 | 存储型 XSS 可窃 localStorage token | 统一走转义函数；token 可考虑改 HttpOnly Cookie |
| 升级无迁移 runner | `migrations/*.sql` 靠人工执行、无版本表 | 建议引入轻量迁移版本表 |
| 单 worker | compose 单进程 uvicorn | 高并发场景再调 worker 数（注意内存限流随之失效，需换 Redis） |

> 限流为单进程内存实现，**多 worker 部署时需替换为 Redis/DB 共享计数**。

## 五、国产库（达梦/金仓）切换要点
1. 用目标库执行 `sql/wms_dm.sql` 或 `sql/wms_pg.sql`（DDL 已由生成器转为对应方言，独立 CREATE INDEX、IDENTITY 自增）。
2. `DB_URL` 指向目标库（方言由连接串自动识别，无需改代码）。
3. 部署前建议用厂商 DTS 迁移工具二次校验；切库后跑一遍 `selfcheck.py` 指向新库。
4. `portable_audit.py` 保证后端无 MySQL 专有 SQL 残留（反引号 / `LIMIT :o,:n` / `ON DUPLICATE KEY` 等均走 dialect 抽象）。

## 六、故障速查
- **登录返回 429**：触发限流，等 5 分钟或重启服务；正常防爆破，勿慌。
- **启动报 `WMS_JWT_SECRET` 相关错误**：生产模式未配密钥/过短，按第一节配置后再启动。
- **服务起来但登录 500**：多为数据库表缺失/连接问题，查 `docker logs <api容器>`；空库请确认 `sql/wms.sql` 已初始化。
- **AI 问数卡一下才出结果**：外网网关超时后回退本地规则（`mode=rule`），核心数据仍来自本库。
- **数据找回**：确认数据卷 `mysql_data` 存在；误删容器不会丢卷，重建容器挂回同名卷即可。
