# 项目计划书（为什么这么做）V2 冻结版

> 状态：意图已冻结（用户 2026-09-19 确认）。本文只定方向与边界，不含实现细节。
> 流程：讨论 → 方案 → 改代码 → 定版后归档文档 → git。

## 1. 目标

- 业务目标：替代手工台账，`DJ登记 → RK入库 → LY领用 → TL退料 → PD盘点`全走审批过账，解决账实不符。
- 溯源目标：批次 `BT` 级 5 秒出链，任抽一批出 `供应商/送货单 → DJ → RK（照片）→ 库位 → LY（人/车间）→ TL/TK → CP/JJ`；盘点差异 3 次点击到人到单。
- 智能目标：`Text2SQL` 问答查三域（业务记录 docs＋库存＋流水），`PaddleOCR` 只做 PC 送货单候选识别。AI 只读、只给候选，不记账。

## 2. 范围

- MVP 只做 `DJ / RK / LY / TL / PD`。`DB调仓 / JJ交付 / ZS直送`进二期，入口置灰，不新增页。
- 页面：PC `pages/docs.html` 为统一溯源主入口，`receipt.html` 加 OCR 候选框、`docs.html` 加问答框；PDA `screens/scan|data|home` 只做扫码＋溯源直达，不做 AI 问答、不做 OCR。
- 不做：单件 `SB` 级一码到底（只到批次聚合）；全系统无手写签名；国产化只到模型层，不碰芯片/OS/DB 选型。

## 3. 架构

- PC：`pages/*.html + assets/store.js`，走 `/api/v1/web/*`。
- PDA：`mobile-app/screens/*.html`，经 `api-client.js(AppApi)` 走 `/api/v1/app/*`，扫码经 `pda-scan.js`（键盘楔回车先行，广播等厂家文档只改此一处）。
- AI 网关（新增薄层）：`POST /ai/ask`、`POST /ai/text2sql`、`POST /ai/ocr`。页面不直调模型，部署前后只换网关 `base_url + key`：
  - 现阶段：`base_url = 阿里百炼 DashScope 兼容接口`，`PaddleOCR` 同走线上兼容接口先行。
  - 部署后：`base_url = 内网 vLLM（Qwen2.5-7B-FP8 离线）`，`PaddleOCR` 切本地，页面零改。
- 数据源：`app-data.js(FieldDB)` 为原型种子；真实环境后端三表 `docs / stock / ledger` 只读提供问答。

## 4. 数据流

- 记账流（人驱动）：工单 → 审批 → `FieldDB.post()` 幂等过账 → 改 `on_hand/avail` → 写 `stock_ledger + audit_log`。断链（缺码/缺批/缺关联）禁过账。
- 溯源流（读）：条码 `SB` → 批次 `BT` → 去向聚合；`docs.html?code=` 与 PDA `data.html?code=` 同码同链；`Σledger = on_hand`，不平锁维度。
- 问答流（只读）：自然问 → 网关拼 `scope + 三域 schema` → Qwen 生成 SQL → 网关白名单校验 → 只读账号执行 → 回表格＋原文 SQL 可审。禁 `INSERT / UPDATE / post / 过账 / 确认验收`。
- 识别流（候选）：PC 送货单图 → Paddle → 回 `{候选值， conf， ocrId}` → 低置信标红 → 人工覆盖才入单。PDA 拍照只做存证（`photoField` 压 1024px / jpeg0.7 / ≤6 张），不做 OCR。

## 5. 关键设计原则

- 简洁优先：`register.html?biz=DJ|RK|LY|TL` 一页四态，不复制三页；溯源不新建页，只链到 `docs.html`。
- 手术式修改：只触碰需求行；`check/all/checklist.js` 已归档 `prototype/_archive/mobile-legacy/`，不删除。
- AI 禁过账：模型幻觉不可记账，记账权只留给人＋审批；后端写接口对 AI 账号直接拒绝。
- 离线优先：弱网进 `queue / mobile_sync_queue`，联网 `sync / flush`；签名已全系统下线，以登录账号＋照片存证为准。
- Karpathy 准则：先说假设与困惑，不默选；能 50 行不写 200 行。

## 6. 技术选型

| 分层 | 选型 | 为什么 |
| --- | --- | --- |
| 问答模型 | Qwen2.5-7B FP8 | 国产、7B 内网 vLLM 可跑，过渡期百炼线上 API 兼容，切换只改配置 |
| OCR | PaddleOCR | 国产，送货单中文 printed 体成熟；先线上兼容，后本地，不动页面 |
| 推理服务 | 内网 vLLM 离线部署 | 监狱离线硬约束；过渡期用 DashScope，接口兼容 |
| PDA 扫码 | 键盘楔回车先行 | 无文档可联调；`pda-scan.js` 留 `PdaScanFeed` 唯一广播入口 |
| 原型 | 静态 `screens/*.html` ＋ `FieldDB` | 无构建、WebView 可装；`app.js` 动态视图已归档为组件，不双轨 |

## 7. 风险与待验证项

- R1 真实数据走线上 API（用户已确认）：合规与费用按百炼计，后端日志记调用；切内网后关闭外访。待验证：百炼 QPS 与 SQL 生成稳定性。
- R2 PDA 厂家文档未到：广播 Intent 名与键格式未定，现冻结键盘楔。待验证：PDA 键扫回车＋振动＋重复码拦截。
- R3 后端索引未建：`barcode / batch_no / doc_no` 三索引与 `doc_attachment` 表在二期。待验证：`Σledger = on_hand` 对账。
- R4 OCR 置信阈值未定：低置信标红＋人工覆盖为强制。待验证：送货单实拍准确率。
- R5 Text2SQL 越权：网关白名单＋只读账号＋行数上限为强制。待验证：写操作一律被拒，原文 SQL 可审计。
