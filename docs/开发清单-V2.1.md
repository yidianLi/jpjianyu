## 一、决策清单（Q1-Q13 落锤）

- D1 范围：MVP 只做 `DJ/RK/LY/TL/PD`，`DB/JJ/ZS` 二期置灰，一步步来，先动 `docs/receipt/dashboard` 三页。
- D2 驾驶舱：PC 新增 `dashboard` 大屏，复用三域 `docs+库存+流水`，手动/按班刷新；看 `KPI+下钻到单+产能`，无设备、无人均、无当班人数。
- D3 产能公式（反推，答案须附公式原文）：
  - 发料量 `Σledger WHERE biz='LY'`
  - 成品入库 `Σledger WHERE biz='RK' AND material_code LIKE 'CP-%'`
  - 退料率 `Σ(TL)/Σ(LY)`（同单位分组，异单位分开展示）
- D4 问答口径：三域只读，默认查快照 `stock_onhand`，仲裁查 `stock_ledger` 汇总；不平以流水为准，只报警不锁，不拦过账；答案不含照片/OCR 候选，只给数和单号+公式。
- D5 AI 禁过账：`Text2SQL` 仅单条 `SELECT`，禁 `INSERT/UPDATE/DELETE/post/过账/确认`；`PaddleOCR` 只给候选，人工覆盖才入单。
- D6 模型与国产化：`Qwen2.5-7B-FP8 + PaddleOCR` 仅模型层国产；先百炼线上 API（含真实数据，用户担合规费用），后切内网 vLLM+本地 Paddle，只改 `ai-gateway.yaml`。
- D7 PDA：装机等厂家文档，现状冻结 `scan/data` 样式，只验键盘楔回车；广播到后只改 `pda-scan.js` 一处。
- D8 缺关联：缺码/缺批/缺关联不拦单，三处标出待处理（工单行标红→docs 补关联；时间线断点标 `缺XX`+嫌疑置顶；驾驶舱异常卡汇总直达处理）。原型只验标出+可补。
- D9 直达：驾驶舱异常卡直达 `docs.html?code=` 与 `stocktake.html?pd=`，仅 PC，PDA 不做。
- D10 存证：全系统无手写签名，以登录账号+照片为准；弱网进队列，过账 `FieldDB.post()` 幂等。

- `prototype/pages/receipt.html`：新增 `#ocrBox` 候选框，低置信标红，人工覆盖才入单（P5）。

- `prototype/pages/stocktake.html`：差异行 `查去向` 带参跳 `docs.html?code=`；驾驶舱支持 `?pd=` 直达差异行。

## 四、验收标准（P0-P7）

- P0 基线：无 `transfer.html` 死链，`git log` 可回放。
- P1 溯源闭环（7 处，PC/PDA 同码同链）：`SB/BT/单号/LY/TL/PD` 各抽 2 个＋1 个盘点差异 `PD` 直查；嫌疑可点；缺关联标出+可补，不拦单。
- P2 驾驶舱：异常卡 1 点击到 `docs`/`stocktake` 单，手动刷新一致，公式随答案展示。
- P3 网关 Mock：无 key 可演示；写 SQL 一律被拒，`ai_qa_log` 可审。
- P4 问答：库存/单据/流水各 3 问出数，原文 SQL 可审，无图。
- P5 OCR：低置信须人工改才能存，候选进 `ocr_*` 表。
- P6 线上真调：真实数据可用，费用/日志可查，页面零改。
- P7 切内网：改配置即可，断外网可用，同问结果一致，关闭外访。
