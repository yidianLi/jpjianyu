## 四、如何复跑

```bash
# 1) 全量巡检(写入型,自建自清标记 handler=walk)
python backend/functional_walk.py
# 2) 仅只读入口
python backend/functional_walk.py --skip-write
# 3) 生产首登账号不同时:
python backend/functional_walk.py --admin-user <管理员> --admin-pass <口令>
```

- 脚本末尾生成 `output/walk_cleanup.sql`（本次产生的单据/报表/账号的**精确**清理脚本）：
  `mysql --default-character-set=utf8mb4 -uroot wms < output/walk_cleanup.sql`
- 退出码：0=全通过；1=有 FAIL；2=登录失败。可直接接入 CI。

> 巡检写入的数据均带 `handler=walk` / 批次 `WALK-*` / 客户 `巡检客户` / 账号 `walk_*` 标记，
> 过账类单据不便经接口回滚，跑完用清理脚本删净即可，不触碰演示数据。

| 1 | 工单按BOM领料返回 500 | `wo_issue` 先 SELECT 再 `with db.begin()`，会话已有事务 | 该函数 `with db.begin()` 前补 `db.rollback()` |

## 六、已知边界

- 动作权限对**写/审批/过账/确认/修改/导出/查看(运行类)**生效；只读 GET 默认放行以保可用。
- `data_scope`（按仓/客户隔离数据）仍为单单位不启用；接入多仓隔离时基于 `perms.effective().data_scope` 过滤。
- PDA 现场作业 APP 为独立入口（`/app`、移动端），不在 PC 菜单，本清单不含其用例。
- 外部依赖类（AI问数/OCR）需外部服务，巡检未纳入自动断言。
